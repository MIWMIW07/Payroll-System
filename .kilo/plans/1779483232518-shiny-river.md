# Plan: Create staff-profile.html for Admin Staff Role

## Problem

The **admin staff** role (`admin-staff` / `admin`) has no dedicated `staff-profile.html` file. The role's pages (`dashboard-staff.html`, `my-attendance.html`, `my-payslips.html`) all link to `profile.html`, which **does not exist anywhere in the project**. This means any admin staff or guard/user clicking the "Profile" nav link gets a **404 error**.

By contrast, the **teacher** role has a complete, fully-featured `teacher-profile.html` with personal info, account info, emergency contact, and change-password modal — all backed by live employee data from IndexedDB.

- All three shared "my-*" pages (`dashboard-staff.html:38`, `my-attendance.html:37`, `my-payslips.html:37`) have a "Profile" nav link pointing to `profile.html`

## Plan

### Step 1 — Create `staff-profile.html`

Borrow structure from `teacher-profile.html`, adjusted for admin staff:

- **Navbar**: title "Philtech GMA - Admin Staff Portal" (replacing the generic "Philtech GMA" in dashboard-staff), roles listed as `Dashboard`, `My Attendance`, `My Payslips`, `My Profile` with the middle three linking to `dashboard-staff.html`, `my-attendance.html`, `my-payslips.html`
- **Avatar avatar**: `?u=staff` avatar image, icon `fa-user-tie` on the card header
- **Heading**: "My Profile" with role label "Admin Staff"
- **Personal Information section** (same field set as teacher): Full Name, Employee ID, `position`, `department`, `email`, `phone`, `hire_date`, `status`
  - Default position: "Admin Staff", department: "Administration"
- **Account Information section**: `username`, masked password, `lastLogin`, `created_at`
- **Emergency Contact section**: `emergency_contact`, `emergency_relation`, `emergency_phone`
- **Action buttons**: Change Password (opens modal), Contact HR, Logout
- **Change Password Modal**: current / new / confirm fields, validation (min 6 chars, match confirm), calls `updatePassword()`
- **JS**: `loadProfileData()` querying IndexedDB via `Database.getAllEmployees()` matching on email/employee_id; sets all DOM fields and formats dates identically to `teacher-profile.html`

### Step 2 — Update `navigation.js`

In the `rolePages` block (lines 67–78), change `'profile.html'` → `'staff-profile.html'` for the `admin-staff` and `admin` entries:

```js
    'dashboard-staff.html',

```

## Notes

- The `teacher-profile.html` naming convention (`teacher-*.html`) already gives a clear pattern — `staff-profile.html` maintains the existing `my-*` / `dashboard-staff.html` naming used by the guard/sa/admin-staff group, **and** avoids the broken generic `profile.html` name entirely.
- Guard (`dashboard-guard.html`) and SA (`dashboard-sa.html`) share the same `profile.html` bug; they are included in this plan and updated to point to `staff-profile.html` for consistency (they will take no further action besides the redirect fix).
- All profile page scripts load `js/database.js`, `js/navigation.js`, `js/csrf.js`, `js/xss-protection.js`, `js/secure-ajax.js` — same as `teacher-profile.html`.
- No backend API changes are needed; employee data is already available via IndexedDB `Database.getAllEmployees()`.

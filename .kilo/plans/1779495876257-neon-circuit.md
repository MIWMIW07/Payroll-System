# Plan — Fix 404 on /api/attendance/admin-master (guard dashboard)

## Root cause
`dashboard-guard.html:243` calls `Database.getAttendanceByEmployee(employeeId)` **without**
passing a `tabType`. Inside `getAttendanceByEmployee` (`js/database.js:364-381`), when
`tabType` is `null` the function falls into the else-branch (line 378) which calls
`getAllAttendance()` → `api.getAttendance('admin-master')` → `GET /api/attendance/admin-master`.
The `api/attendance/admin-master.php` endpoint requires `period_start` and `period_end` query
parameters; with none supplied it immediately calls `jsonError('Missing period_start or period_end', 400)`
(`admin-master.php:80-82`). The fetch-wrapper in `ApiIntegration.call()` / fallback `call()`
throws `Error('API Error: 400')` / `Error('API Error: 404')`, which is what the browser console
reports as a 404 (or the production server returns 404 when `router.php` can't resolve the
bare path).

## Call chain (broken path)
```
DOMContentLoaded @ dashboard-guard.html:195
  → loadGuardData() :231
    → loadAttendance() :243
      → Database.getAttendanceByEmployee(employeeId)   ← no tabType
        → getAllAttendance() :378 (else-branch)
          → api.getAttendance('admin-master')          ← no period_start/period_end
            → GET /api/attendance/admin-master 404
```

## What needs to change

### 1 · `dashboard-guard.html` — pass `'guard'` as `tabType`
At line 243 change:
```js
allAttendance = await Database.getAttendanceByEmployee(employeeId);
```
to:
```js
allAttendance = await Database.getAttendanceByEmployee(employeeId, 'guard');
```
This routes via the if-branch at `database.js:365-376` which calls
`api.getAttendance('guard')` → `GET /api/attendance/guard`.  
`api/attendance/guard.php` GET requires no mandatory query params — it returns all
attendance records or filters by `period_start`/`period_end` when provided — making it
safe for the dashboard's "show all" initial load.

### 2 · `router.php` — extract `type` from path and inject `$_GET['type']`
Add a new block **before** the existing `if (strpos($uri, '/api/') === 0)` block at line 22
of `router.php` so that bare-path `/api/attendance/{type}` requests have their `type`
segment automatically available as `$_GET['type']` when the target script is
`attendance.php`:

```php
// Unified attendance routes: /api/attendance/{type}?params  →  /api/attendance.php?type={type}&params
if (strpos($uri, '/api/attendance/') === 0 && strpos($uri, '.php') === false) {
    $attendType = substr($uri, strlen('/api/attendance/'));
    if (!empty($attendType)) {
        $_GET['type'] = $attendType;   // inject type for attendance.php
    }
}
```

Files affected: `js/database.js`, `js/dashboard-common.js`, `dashboard-guard.html`, `dashboard-sa.html`, `router.php`.

### 3 · `router.php` — fix path diffing when query string present
Change `router.php`'s API-match condition to strip the query string and avoid accidental
`file_exists` hits on files with embedded query params (cosmetic but more robust):

```php
$pathOnly = parse_url($uri, PHP_URL_PATH);   // strip ?… fragment

// Unified attendance routes
if (strpos($pathOnly, '/api/attendance/') === 0 && strpos($pathOnly, '.php') === false) {
    $attendType = substr($pathOnly, strlen('/api/attendance/'));
    if (!empty($attendType)) {
        $_GET['type'] = $attendType;
    }
    $pathOnly .= '.php';          // /api/attendance/guard  →  /api/attendance/guard.php
    $phpFile = __DIR__ . $pathOnly;
}

// API routes
if (strpos($pathOnly, '/api/') === 0) {
    $phpFile = __DIR__ . $pathOnly . '.php';
    ...
}
```

With this in place, any `GET /api/attendance/guard`, `GET /api/attendance/sa`, or
`GET /api/attendance/admin-master` that maps to a dedicated `.php` file works as before;
any other sub-path (e.g. `summary`, `eda`) falls through to `attendance.php?type=…`
which receives `$_GET['type']`.

Admin dashboard (`dashboard-sa.html:225`) calls `getAttendanceByEmployee(employeeId)` without `tabType` — apply the same `'sa'` fix; standalone SA pages already pass `roleType`.

This resolves the 404 on `dashboard-guard.html` and ensures `getAttendanceByEmployee` uses the correct role-specific endpoint across roles.
